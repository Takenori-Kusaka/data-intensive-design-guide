## 何の資料か

マイクロサービスと共通基盤（データ・ETL・ログ・認証・AI・分析・セキュリティ）から成る大規模クラウドサービスの全体像を、データ指向の考え方で、柔軟性・拡張性・置換性・更新性を保って設計する。そのための**判断の材料**と、**設計レビューで問う観点**をまとめた。

本の要約ではない。『データ指向アプリケーションデザイン 第2版』を地図として使い、標準・製品の公式文書・事業者の事後報告で裏を取り直した。

## 読者

新任のテックリーダー。RDB と Web アプリの開発経験はあるが、分散システムの理論は体系的に学んでいない人。用語は定義と図から説明する。

## 根拠の読み方

各スライドの下の行が根拠。3 種類ある。

- **仕様・文書**：標準、製品の公式文書（版と確認月つき）、原論文
- **指針・報告**：公的機関とクラウド各社の設計指針（任意の推奨）、事業者の事後報告（自己申告）
- **書籍**：章・節・印刷ページ。「（考え方）」は一般論として借りた印

一次資料で裏づけられない主張や、本ガイドによる整理には「本ガイドの考え」の印を付けた。

## 限界（使う前に読んでほしいこと）

- **実測はまだ含まない。** ケーススタディ（データ統合／置換と更新／ログ・分析の費用と性能／整合性の異常）はこれから測る。スライドの「ケーススタディ」の注記は、測る予定の点を示す
- クラウドのマネージド製品の記述は公式文書によるもので、実機では確かめていない（「未検証」と表示）
- 事後報告は事業者の自己申告。件数の分類と型への割り当ては本ガイドによる。公開する事業者に偏るので、業界全体の頻度ではない
- 規格の本文（ISO/IEC 25010:2023、JIS X 25010:2025 など）は確かめていない。定義文は引用せず、特性の名前の対応だけを使った。JIS の訳語は二次資料による
- 法に関わる記述は、設計の段階で決めておく点を示すもので、法的な助言ではない
- 製品の版・既定値・日付は 2026 年 11 月の調査時点のもの

## 検証の進め方

1. 各 Part の書き手が、載せる数字・版・既定値・日付・書籍のページを原典で確かめた
2. 全スライドの画像を 1 枚ずつ見て、配置を直した
3. 書き手とは別の 12 担当が、3 つの観点（標準と論文／製品と事後報告／書籍と機関）で一次資料と照合した（指摘 188 件）
4. 指摘は、反映の担当が一次資料で確かめてから直し、全件を記録した

詳しくは [research/reviews/factcheck-2026-11-18.md](research/reviews/factcheck-2026-11-18.md)。

## 作り直し方

```bash
cd deck && npm install                       # 初回だけ（pptxgenjs など）
node build.js guide.pptx                     # pptx を組み立てる
node build_one.js p06                        # 1 Part だけ組み立てて確かめる
powershell -File qa.ps1 -pptx <pptx の絶対パス> -outDir <出力先>    # 画像の書き出しと、はみ出しの検査（PowerPoint が要る）
python ../tools/build_web_slides.py          # Web 版
python ../tools/prepublish_check.py          # 公開前の検査
```
