# データ指向の考え方による大規模クラウドサービスの全体設計 依頼の整理（brief・公開版）

作成日：2026-11-18。依頼者との対話で固めた内容のうち、資料の目的・読者・範囲に関わる部分をまとめた。

## 背景

- 新任のテックリーダーに、データ基盤を含むシステム全体の設計判断を任せたい。チームの設計レビューで使う共通の基準もほしい
- 依頼者自身も、全体像を自分で設計できるようになりたい
- きっかけの書籍：『データ指向アプリケーションデザイン 第2版』（Martin Kleppmann・Chris Riccomini 著、斉藤 太郎 訳、オライリー・ジャパン、ISBN 978-4-8144-0180-2）

## 目的（この資料で読者ができるようになること）

- 大規模クラウドサービスの全体像を、データ指向の考え方で、決まったステップに沿って自分で設計できる
- 設計レビューで問うべき観点を持ち、根拠（一次資料・書籍の該当ページ・実測）を示して判断を説明できる

## 読者と前提知識

- 新任のテックリーダー。RDB と Web アプリの開発経験はあるが、分散システムの理論は体系的に学んでいない
- 用語は基礎から説明する（B ツリーと LSM ツリー、分離レベル、線形化可能性、合意などは定義と図から）

## 焦点

マイクロサービス構成の大規模クラウドサービス（共通のデータ基盤・ETL・ログ・認証・AI・分析・セキュリティの各基盤を持つ）を設計する人が、データ指向の考え方で、柔軟性・拡張性・置換性・更新性の高いシステムの全体像を、どんなステップで考えて押さえるか。個々の DB 技術の解説はそのステップを支える基礎として扱い、主役は「全体を自分で設計できるシニアエンジニアの考え方の手順」。

- 本の位置づけ：本全体が題材。ただし本の要約ではなく、本を地図として使い、一次資料と実測で裏を取り直す
- 構成の軸：本の章立てではなく、判断の問い（設計のステップ）で再構成し、各 Part から本の該当章へ対応づける
- 第 2 版の更新点：独立して取り上げず、内容に織り込む

## 扱う論点

- 柔軟性、拡張性、置換性、更新性の高いシステム構築
- どのようなステップで考えて全体像を押さえるか
- 共通のデータ基盤、ETL 基盤、ログ基盤、認証基盤、AI 基盤、分析基盤、セキュリティ基盤
- サービス間のデータの流れ（記録のシステムと導出データ、CDC・イベントログ・ストリームによるデータ統合、サービスごとの DB と共通基盤の境界）
- 置換性・更新性（スキーマの進化と互換性、データ契約、逐次更新、基盤や DB を差し替えられる設計、再処理）
- 正しさと障害（レプリケーション・シャーディング・トランザクション・一貫性と合意、サービスをまたぐ整合性、部分障害）
- 共通基盤ごとの設計

## 対象の製品・実装

- 実機（ケーススタディ）：PostgreSQL、MySQL、Kafka 互換のブローカーと Debezium、スキーマレジストリ、ClickHouse、DuckDB、CockroachDB
- 公式文書に基づく比較（未検証と明記）：Aurora、Spanner、DynamoDB、BigQuery、Snowflake など

## ケーススタディの題材

1 つの架空のサービス（業務サービスと共通基盤）を組み、その上で 4 つを測る。

1. 基盤をまたぐデータ統合：二重書き込みとアウトボックス、CDC を比べ、障害を入れて欠落・重複・順序のずれを数える
2. 置換と更新の演習：稼働中のスキーマ変更、導出ストアの差し替え、ログからの再構築
3. 共通基盤の費用と性能：ログ・分析を、行指向・列指向・ファイルで比べる
4. 整合性の異常の再現：分離レベルごとの異常、古い読み取り、フェイルオーバーでの損失

結論の型は、共通の基準＋題材ごとの重点＋見送り（何を失うか、見直しの条件つき）。
